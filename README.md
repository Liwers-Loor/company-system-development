# 建筑工程智能化三系统 Vibecoding 项目

这个仓库承载 ERP、CRM、FMS 三个系统的任务书、Spec、协作记录和交付证据。

三个系统分别由三名实习生认领。项目通过 GitHub Issue、分支、提交、工作日志和 Pull Request 留下完整过程。

## 从这里开始

1. 阅读对应的任务书。
2. 在 GitHub Issue 中认领 ERP、CRM 或 FMS。
3. 阅读 AGENTS.md 和 SPEC模版.md。
4. 建立任务分支。
5. 为第一个业务动作创建 Spec。
6. 使用 AI Agent 施工、验证并提交工作日志。
7. 推送分支并创建 Draft PR。

## GitHub 文档优先级

- 任务书决定系统边界
- SPEC 决定单个业务动作的交付内容
- 统一数据底座协商记录决定共享字段和接口
- GitHub Issue 决定当前任务
- 工作日志和 Pull Request 记录实际过程与验证结果

## 共享约束

CRM、ERP、FMS 必须围绕同一个客户、同一个项目和同一组来源记录完成联调。

共享字段、接口含义、回写规则和冲突处理方式由三名实习生共同协商，并记录在统一数据底座协商记录.md 中。

## 版本冻结

第 7 周三系统联调验收结束后冻结 MVP，并生成版本标签。

第 8 周围绕冻结版本进行 GUI、Logo、资源和风格统一。新增业务需求进入下一版本列表。
